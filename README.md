# Blazentenance

Professional network-wide maintenance plugin for the **BlazeMC Network**.

Blazentenance is built for **Velocity 3.x** proxies with **Paper 1.20.x / 1.21.x** backends, including 1.21.11. Maintenance is controlled from the Velocity proxy, not from individual Paper servers. The Paper module exists to stop players from bypassing maintenance by connecting directly to a backend IP.

| Artifact | Install on | Role |
|---|---|---|
| `Blazentenance-Velocity.jar` | Velocity proxy | Authority for maintenance, commands, whitelist, and connection blocking |
| `Blazentenance-Paper.jar` | Every Paper backend | Direct-connection protection and signed proxy handshake |

Java 21+ is required.

---

## 1. How to build with Maven

Requirements:

- JDK 21 or newer
- Maven 3.8+

From the project root:

```bash
mvn -DskipTests=false clean package
```

The shaded plugins are written to:

```text
dist/Blazentenance-Velocity.jar
dist/Blazentenance-Paper.jar
```

Copies are also available in:

```text
Blazentenance-Velocity/target/Blazentenance-Velocity.jar
Blazentenance-Paper/target/Blazentenance-Paper.jar
```

---

## 2. Install Blazentenance-Velocity.jar

1. Stop the Velocity proxy.
2. Copy `Blazentenance-Velocity.jar` into the Velocity `plugins/` folder.
3. Start Velocity once so the plugin can generate its files.
4. Confirm the log contains `[Blazentenance] loaded`.
5. Copy `security.shared-secret` from the generated Velocity config into every Paper Blazentenance config (see section 6).

Velocity data directory:

```text
plugins/blazentenance/
```

---

## 3. Install Blazentenance-Paper.jar on every backend

Install the Paper module on **every** Paper server behind the proxy: lobby, survival, minigames, and anything else players could reach.

1. Stop the Paper server.
2. Copy `Blazentenance-Paper.jar` into that server's `plugins/` folder.
3. Start Paper once to generate `plugins/Blazentenance/config.yml`.
4. Paste the Velocity `security.shared-secret` into the Paper config.
5. Restart Paper.

Do not install only the Paper jar. Without Velocity, there is no network-wide maintenance control.

---

## 4. Configure Velocity

Edit `velocity.toml` in the Velocity working directory.

Recommended values:

```toml
online-mode = true
player-info-forwarding-mode = "modern"
forwarding-secret-file = "forwarding.secret"
```

`forwarding.secret` is generated by Velocity. Do not commit it, paste it in public chats, or print it in logs.

Firewall the proxy host so Minecraft clients can only reach Velocity (usually `25565`). Paper backend ports must not be public.

---

## 5. Configure Paper

On every Paper backend:

### `server.properties`

```properties
online-mode=false
```

The proxy authenticates players. Paper must not.

### `spigot.yml`

```yaml
settings:
  bungeecord: false
```

Do not enable legacy BungeeCord forwarding when using Velocity modern forwarding.

### `config/paper-global.yml`

```yaml
proxies:
  velocity:
    enabled: true
    online-mode: true
    secret: "PASTE-THE-CONTENTS-OF-VELOCITY-forwarding.secret"
```

`online-mode` here must match `online-mode` in `velocity.toml`.

On Paper 1.18.2 or older the same keys live under `settings.velocity-support` in `paper.yml`.

Restart every backend after changing forwarding settings.

---

## 6. Configure modern forwarding

Modern forwarding is the required security boundary. Paper natively rejects connections that do not present a valid Velocity HMAC during login.

Checklist:

1. Velocity: `player-info-forwarding-mode = "modern"`.
2. Velocity: `forwarding.secret` exists and is at least 12 characters.
3. Paper: `proxies.velocity.enabled: true`.
4. Paper: `proxies.velocity.secret` is **exactly** the Velocity forwarding secret.
5. Paper: `online-mode=false`.
6. Paper: BungeeCord forwarding is disabled.
7. Blazentenance Velocity and Paper `security.shared-secret` values match.

Blazentenance adds a second signed handshake on channel `blazentenance:auth`. That secret is **not** the Velocity forwarding secret. Velocity generates `security.shared-secret` on first start. Copy it into every Paper `plugins/Blazentenance/config.yml`.

Clients cannot spoof this channel. The Velocity plugin marks those plugin messages as handled and never forwards client packets to backends.

## 7. Where `config.yml` is located

Velocity:

```text
plugins/blazentenance/config.yml
```

Paper (each backend):

```text
plugins/Blazentenance/config.yml
```

Both files are created automatically on first start.

The Velocity file stores the persisted maintenance flag:

```yaml
maintenance:
  enabled: false
```

If maintenance is ON when Velocity restarts, it stays ON.

Default kick message:

```yaml
maintenance:
  kick-message:
    - ""
    - "&c&lBLAZEMC NETWORK"
    - ""
    - "&cServerul BlazeMC Network este în lucru!"
    - "&7Revenim în curând!"
    - ""
    - "&eMulțumim pentru înțelegere!"
    - ""
```

`&` color codes, `&#RRGGBB` hex colors, multi-line messages, and optional MiniMessage (`messages.format: MINIMESSAGE`) are supported.

---

## 8. Where `players.yml` is located

Velocity whitelist:

```text
plugins/blazentenance/players.yml
```

Created automatically. UUID is the primary identifier. Usernames are stored for display and name-based removal.

Example:

```yaml
players:
  069a79f4-44e9-4726-a5be-fca90e38aaf5:
    name: Notch
    added-at: 2026-01-01T00:00:00Z
```

## 9. Commands

All maintenance commands run on the **Velocity console** and in-game for administrators.

Main command: `/blazemaintenance`

Aliases: `/blazentenance`, `/bmaint`, `/maintenance`

| Command | Description |
|---|---|
| `/blazemaintenance` | Shows command help |
| `/blazemaintenance on` | Enables global maintenance |
| `/blazemaintenance off` | Disables maintenance |
| `/blazemaintenance add player <playername>` | Adds a player to the whitelist |
| `/blazemaintenance remove player <playername>` | Removes a player from the whitelist |
| `/blazemaintenance list` | Lists authorized players |
| `/blazemaintenance status` | Shows whether maintenance is ON or OFF |
| `/blazemaintenance reload` | Reloads configuration without a restart |

Console responses:

```text
[Blazentenance] Maintenance mode has been ENABLED!
[Blazentenance] Maintenance mode has been DISABLED!
```

Tab completion is supported. Duplicate whitelist entries are rejected. Players can be added by username or UUID. On online-mode proxies, unknown names are resolved through Mojang. On offline-mode proxies, offline UUIDs are generated.

The Paper `/blazemaintenance` command only shows backend protection status and can reload the Paper config. It cannot toggle network maintenance.

---

## 10. Permissions

| Permission | Description |
|---|---|
| `blazentenance.admin` | All Blazentenance commands |
| `blazentenance.bypass` | Join during maintenance without being whitelisted |

The Velocity console always has full access. In-game staff need `blazentenance.admin` on the **proxy** (LuckPerms-Velocity or equivalent). `blazentenance.bypass` is also checked on Velocity during login.

---

## 11. How the global maintenance system works

### Maintenance OFF

- The network operates normally.
- Every player can join through Velocity.
- Players can connect to all backend servers.
- No maintenance kick or whitelist check is applied.
- Direct backend connections are still blocked when Paper protection is enabled.

### Maintenance ON

1. Velocity `LoginEvent` is the primary gate. Unauthorized players are kicked before they reach any Paper server.
2. `ServerPreConnectEvent` blocks backend switches as a second layer.
3. Only whitelist members and players with `blazentenance.bypass` may join.
4. Unauthorized players receive the configured kick message.
5. Already connected players are kicked only if `maintenance.kick-existing-players.enabled` is `true`. Whitelisted and bypass players are never kicked by that option.
6. The Paper module requires a signed Velocity handshake. A player who reaches a backend without that handshake is kicked.
7. Paper never trusts client plugin messages or unsigned forwarding data.

Velocity is the only place that decides who is authorized. Paper enforces the decision it receives from the proxy.

## 12. Troubleshooting

**Unauthorized players still join**

- Confirm `Blazentenance-Velocity.jar` is in the Velocity `plugins/` folder and loaded.
- Run `/blazemaintenance status` on the Velocity console.
- Confirm you are connecting to the proxy port, not a Paper port.

**Players can join Paper directly**

- `proxies.velocity.enabled` must be `true`.
- Paper `secret` must match Velocity `forwarding.secret`.
- Backend ports must not be exposed publicly.
- Paper `security.shared-secret` must match Velocity.
- `backend-protection.require-proxy-handshake` must stay `true`.

**Whitelisted player is still kicked**

- Use `/blazemaintenance list` and confirm the UUID.
- Online-mode networks must add the Mojang username, not an offline UUID.
- Bypass permission must be granted on Velocity, not only on Paper.

**UUID could not be resolved**

- Check the username.
- For cracked/offline networks set `settings.uuid-mode: OFFLINE` or `AUTO` with Velocity `online-mode = false`.
- You can add a UUID directly: `/blazemaintenance add player 069a79f4-44e9-4726-a5be-fca90e38aaf5`.

**Shared secret warnings**

- Copy `security.shared-secret` from Velocity to every Paper config.
- Never put the Velocity `forwarding.secret` into Blazentenance `shared-secret`. They are different keys.

**Kick message has no colors**

- Use `&` codes (`&c`, `&l`, `&#FF5555`) or MiniMessage if `messages.format` is `MINIMESSAGE`.
- Reload with `/blazemaintenance reload`.

**Maintenance resets after restart**

- Do not delete `plugins/blazentenance/config.yml`.
- `maintenance.enabled` is rewritten when you run `on` / `off`.
- After editing the file manually, run `/blazemaintenance reload`.

## Security notes

- Do not log or share `forwarding.secret` or `security.shared-secret`.
- Do not rely on BungeeCord legacy forwarding. It can be spoofed.
- Keep Paper ports on a private network or firewall them to the Velocity host only.
- The proxy is mandatory. The Paper module is additional protection, not a replacement.
